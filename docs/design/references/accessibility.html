T05 · Accessibility annotations

Landmarks, focus order and keyboard parity by design

The viewer and editor are designed for keyboard-only operation and WCAG 2.2 AA. This page annotates the intended landmarks, focus order, live regions and chart alternative. It is a design basis, not an axe result or a screen-reader certification.

Focus is never removed A 2 px amber ring with 2 px offset has at least 3:1 contrast on the canvas in both themes. Drawers and sticky bars reserve space for it.
Every core flow Open, mode switch, field binding, add/move/resize, filters, comparison, apply/cancel, reset, realtime pause/resume, chart alternative and plugin recovery have keyboard paths.
Announce, then continue Routine updates are polite. Blocking errors are assertive once. Announcements are visible text too, never sound-only.

Viewer focus order and landmarks

Desktop schematic · DOM order, not visual decoration
1 Skip link First focusable element; jumps to board main.
2 Banner · board identity and title Host, title, provenance, metadata; `header` with an accessible name.
3 Board modes · navigation landmark Viewer/Editor segmented control; arrow keys or Enter/Space.
4 Filters · search/form landmark Active chips, remove actions, Filters, Reset. Origin is written in words.
5 Board region · canvas A labelled region, or `main` in a full-page host; blocks follow in document order.
6 Block title → actions → chart/table Each block is a labelled section; chart summary and data disclosure are reachable.
7 Realtime status and pause/resume Visible status text plus polite live announcement. Pause/resume is a real control.
8 Live region · not in tab order Polite status; assertive alert only for blocking errors, announced once.
  • 1Skip linkVisually hidden until focused; the first Tab stop.
  • 2BannerThe board title is the first heading in the board region; a full-page host may use `main`.
  • 3ModesMode belongs to the view; switching never discards the draft.
  • 4FiltersRemovable chips include the filter name and scope in the accessible name.
  • 5Board regionThe host has exactly one main landmark; the embedded canvas is a region when the host already has one.
  • 6BlocksFocus order stays in DOM order; chart table is the text alternative.
  • 7Live statusThe status is not color-only: dot plus the word “Live” or “Reconnecting”.
  • 8Live outputA pre-existing polite region; no repeated announcements on each render.

Reduced motion, reflow and target size

Plans checked in T18 · not runtime results

Reduced motion

Duration tokens collapse to 0.01 ms, scoped transitions and animations stop, and smooth scrolling is disabled. Loading keeps a static skeleton; charts appear in their final state. A chart animation longer than five seconds has a visible stop control.

320 px and 200 percent zoom

1440 px at 200 percent equals 720 CSS px; 1280 px at 200 percent equals 640 CSS px. Both use the narrow/tablet compositions. No function is removed; the page never scrolls horizontally. Targets remain at least 24 by 24 px.
