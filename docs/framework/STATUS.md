T04 adds dataset, field and slice descriptors with capabilities, timezone and unit metadata; provider contract validation; local fixture and async provider adapters; canonical query keys, request tokens and generations; cancellation and stale-result protection; loading, empty, partial, error, cancelled and stale query states; and space-owned query events and snapshots. Text, metric, table and filter surfaces are production containers. T07 adds the headless renderer contract and registry, the normative field-type matrix, shared value formatting, chart/KPI/table models, ECharts 5.6.0 chart renderers, KPI and table renderers with accessible alternatives, zero-baseline and negative/empty/null policies, custom renderer containment and a renderer gallery. The full editor, filter editing, comparisons and realtime transport remain later tasks.
- Core boundaries: the core package has no DOM, UI framework, server, SQL, ORM or database dependency. Mutable state belongs to a runtime or space instance; module-level exported catalogs are frozen. The core imports and runs in Node without browser globals.
- Space contracts: a runtime creates spaces; each space owns its committed document, draft, undo history, locale/timezone, views, listeners and scheduled tasks. Views own their mode and session context. Disposal is idempotent, cancels owned timers, clears listeners and ignores late callbacks.
- Editor contracts: one editor lease per space, viewer-bound commands reject authoring, mode switches preserve document, draft and history, dirty release requires an explicit apply or cancel decision, and revision conflicts preserve the draft and reject overwrite.
- Localization foundation: locale configuration accepts `en`, `ru`, `es`, `fr`, `de`, `pt-BR`, `zh-CN`, `ja`, `ko`, `ar` and `hi`; only the English message dictionary is built in. Missing keys fall back to English deterministically. Full locale dictionaries, RTL layout and browser localization evidence remain T17 work.
- Workspace: root npm workspace with `packages/core`, `packages/view-dom`, `packages/renderers-echarts`, `packages/react`, `packages/angular`, `packages/svelte`, `examples/` and `apps/demo/`. Planned scoped names are used for tarball consumers only.
- Build and test output: publishable package staging is written to `.tmp/build/packages`, coverage to `.tmp/testing/coverage`, and Vite/Vitest caches to `.tmp/vite`. Source packages do not own generated `dist` directories. `verify:packages` checks staging and the packed tarball surface.
- Public-surface and metadata-input safety: scanners and quality tools classify every path segment and reject protected names, local-only directories, traversal, absolute paths, symlinks and linked ancestors before content reads or writes. Protected values are never printed.
- Legacy preservation: the original non-sensitive source and configuration remain recoverable from the local `LEGACY` branch, which was not pushed. Local database, environment and private-context files were not read, copied or published.
